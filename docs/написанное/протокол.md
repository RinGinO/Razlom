# Справочник протокола

Обмен между клиентом и сервером идёт JSON-сообщениями по WebSocket. Каждое
сообщение — объект с полем `t`. Типы и схемы — в
`packages/protocol/src/messages.ts`.

> **Две известные дыры** — см. [внизу](#известные-дыры). Прочитайте до того,
> как писать сетевой клиент.

---

## Клиент → сервер

Каждое входящее сообщение проверяется zod-схемой **до** того, как попасть в
комнату. Лишние поля не ломают разбор; неверные — отвергаются с `bad-message`.

### До входа в комнату

| `t` | Поля | Что делает |
|---|---|---|
| `create` | `name` (1–24), `roundsPerEpoch` (4, 6, 8) | создаёт комнату, отправитель становится хостом |
| `join` | `roomCode` (4–12), `name` (1–24) | входит в комнату по коду |
| `rejoin` | `roomCode`, `token` (8–64) | возвращает место после разрыва |

Ответ на `create` и `join` — `joined` с ключом `token`. **Его нужно сохранить
на клиенте**: без него после разрыва место не вернуть.

### В комнате

| `t` | Поля | Когда |
|---|---|---|
| `start` | — | лобби; только хост; нужно минимум двое |
| `submit_draft` | `archmage` | фаза `draft` |
| `submit_weaving` | `action` — см. ниже | фаза `weaving` |
| `submit_building` | `action` — см. ниже | фаза `building` |
| `unready` | — | `weaving` или `building`, пока готовы не все |
| `resync` | `since` — номер версии | в любой момент |

**Отправка заявки — это и есть «Готово».** Отдельного сообщения нет.
Отменить можно через `unready`, пока хоть один игрок не готов; сама заявка
при этом остаётся на сервере, её можно отправить заново.

### `submit_weaving` · `action`

```ts
{
  stacks: { fire?: number; water?: number; earth?: number; air?: number; void?: number };
  corruptionTaken: number;                       // 0–16
  exchanges?: Array<{ charmId: string; from: Color; to?: Color }>;   // до 4
  targeted?: Array<{ charmId: string; targetPlayerId: string; node?: NodeId }>;  // до 4
}
```

Числа — целые неотрицательные, до 64. Узел, которого нет в игре, отвергается.

### `submit_building` · `action`

```ts
{
  pick: null | {
    charmId: string;
    overbid: number;                             // 0–64
    pay: { red?: number; blue?: number; … };     // сумма = цена + надбавка
    choice?: Color;                              // только для Столпа и Друида
  };
  consolationColor: Color;                       // цвет утешения при проигрыше в конфликте
  exchanges?: Array<{ charmId: string; from: Color; to?: Color }>;   // Тигель
  druidColor?: Color;                            // Архимаг-Друид, конец Эпохи I
}
```

`pick: null` — пас.

## Сервер → клиент

| `t` | Поля | Когда приходит |
|---|---|---|
| `joined` | `roomCode`, `playerId`, `token` | после `create` и `join` |
| `lobby` | `view: LobbyView` | каждое изменение лобби |
| `snapshot` | `view: PlayerView` | старт партии, смена фазы, после своей заявки, `resync` |
| `patch` | `events: GameEvent[]`, `version` | после разрешения фазы — все автоматические фазы одним пакетом |
| `ready_map` | `ready: string[]`, `version` | каждое изменение готовности |
| `presence` | `playerId`, `connected` | разрыв и возвращение игрока |
| `your_turn` | `phase`, `round`, `version` | стол ждёт **только** этого игрока; один раз на фазу |
| `public` | `view: PublicGameView` | **не отправляется** — см. дыры |
| `error` | `code`, `message` | заявка отвергнута |

### Порядок после разрешения фазы

Сначала `patch` с событиями, потом `snapshot` каждому игроку. Клиент
проигрывает события анимацией, а снимок использует как итоговое состояние.
Сервер к этому моменту уже ушёл вперёд — анимация дело клиента, её можно
пропустить.

### `ready_map` против `snapshot`

О готовности **соперника** клиент узнаёт из `ready_map`, а не из нового
снимка: снимок соперникам при этом не переотправляется. Поле `ready` в
`opponents` снимка отражает момент снимка и устаревает. Источник правды о
готовности — последний `ready_map`.

## `PlayerView` — что видит игрок

Полное описание — `packages/protocol/src/view.ts`. Кратко:

- **всегда:** фаза, эпоха, раунд, Порог, усиленные узлы, узлы, рынок, своя рука
  целиком, соперники без стопок, история по раундам;
- **только своя ставка** — `submitted`, `submittedCorruption`;
- **только в драфте, только своя рука** — `draftHand`;
- **Компас и Провидец** — `nextThreshold`;
- **только Провидец** — `nextEmpowered`;
- **только Око** — `rivalPresence`: на скольких узлах стоят соперники, без сумм.

У кого поле не положено, у того **ключа нет вовсе** — не `null`, не
`undefined`. Проверять через `'nextThreshold' in view`.

История — массив `RoundDigest`: раунд уже разобран по узлам (сумма,
перегрузка, первое и второе места, начисления, Скверна, покупки). Сырые
события в историю не отдаются.

## Версии и `resync`

У состояния монотонная `version`. Она растёт на каждой смене фазы и
приходит в `snapshot`, `patch`, `ready_map`, `your_turn`.

После разрыва клиент шлёт `resync { since: <последняя известная версия> }`:

- версия актуальна → приходит только `ready_map`;
- клиент отстал → приходит полный `snapshot`.

Патчей «с версии N» сервер не хранит: отставший всегда получает снимок
целиком. Это всегда корректно и проще.

## Коды ошибок

**Транспорт:** `bad-json`, `bad-message`, `not-in-room`, `bad-token`,
`internal`.

**Правила** (приходят из ядра и комнаты):

| Группа | Коды |
|---|---|
| комната | `no-room`, `room-archived`, `room-full`, `already-started`, `not-started`, `not-host`, `too-few`, `player-count`, `symmetric-mode` |
| фаза | `wrong-phase`, `too-late`, `missing-action` |
| ставка | `not-enough-mana`, `bad-stack`, `bad-corruption`, `inactive-node` |
| драфт | `not-in-hand`, `already-picked`, `draft-pool` |
| покупка | `not-on-market`, `not-enough-essence`, `payment-mismatch`, `bad-payment`, `bad-overbid`, `needs-color`, `bad-choice` |
| карты | `no-ability`, `no-uses-left`, `not-exchangeable`, `bad-exchange`, `not-targetable`, `bad-target`, `not-activatable`, `bad-color`, `already-declared` |
| предзаявки | `too-many-orders`, `duplicate-order`, `not-adjacent`, `same-node`, `bad-order` |

Клиент должен показывать `message` — он на русском и пригоден для игрока.

## Известные дыры

### Предзаявки не доходят по сети

**Что:** в `weavingSchema` нет поля `standingOrders`, и маршрут
`submit_weaving` в `server.ts` его не передаёт. Ядро и комната предзаявки
понимают, а протокол их выбрасывает.

**Последствие:** по сети не работают **шесть карт** — Иллюзионист, Некромант,
Зеркало, Громоотвод, Немой узел, Жатва. В хот-сите и в тестах ядра они
работают.

**Как исправить:**

1. `protocol/src/messages.ts` — схема предзаявки (триггер и эффект как
   дискриминированные объединения по `type`, повторяя `StandingOrder` из
   `core/src/types.ts`) и поле `standingOrders: z.array(…).max(3).default([])`
   в `weavingSchema`.
2. `server/src/server.ts` — передать `standingOrders` в `room.submitWeaving`.
3. Тест в `protocol/test/messages.test.ts` и сквозной в
   `server/test/fullmode.test.ts`.

Комната уже принимает поле — менять её не нужно.

### Сообщение `public` не отправляется

**Что:** тип объявлен, проекция `room.publicView()` написана и покрыта
тестами, но ни один маршрут её не отдаёт.

**Последствие:** показать завершённую партию по ссылке (§16) нельзя.

**Как исправить:** решить, как запрашивать — отдельное сообщение клиента или
HTTP-маршрут `GET /game/:code` — и отдавать `publicView()` только при
`phase === 'finished'`. Проекция это уже проверяет и бросает исключение для
незавершённой партии. Само решение, раздавать ли ссылку, — за вами, см.
[незакрытое](незакрытое.md).
