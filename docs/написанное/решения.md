# Журнал решений

Развилки, которые встретились по ходу, и что на них выбрано. Здесь только то,
что **не выводится из кода** — причины, а не следствия.

---

## Ботов не будет

**Решение:** боты вычеркнуты из игры целиком.

Спецификация отводила им §10 и предлагала три уровня. Отпало вместе с
рейтингом: игроков немного, лобби заполнять некем и незачем.

**Что за собой потянуло:** из протокола ушли `vote_replace` и `vote_open`,
из состояния — `isBot` и `allowBots`, из §16 сняты два открытых вопроса про
зачёт партий с ботом.

**Чего не потянуло:** симуляция баланса осталась и осталась первой по важности.
Агент для симуляции — не бот в игре: он живёт в `packages/sim`, вызывает ядро
напрямую и никогда не подключается к комнате.

---

## Рейтинга не будет

**Решение:** ELO, таблица матчей и подбор соперников не делаются.

При малом круге игроков ранжировать некого. Вместе с рейтингом отпали меры
§13 против мультиаккаунта по устройству и правило «рейтинговые партии только
со случайным подбором» — без рейтинга они теряют смысл.

---

## Уход игрока: стол ждёт всегда

**Решение:** если игрок ушёл насовсем, партия просто ждёт. Голосования за
исключение нет, досрочного финала нет.

Это буквально §11 правил: «Если голосовать никто не хочет, партия просто
ждёт» — нормальное состояние, а не сбой. Раз ботов нет, заменять место
некем, а в своей компании вопрос решается словами, а не механикой.

**Риск, принятый сознательно:** одна обида — и партия висит вечно.

---

## SQLite вместо PostgreSQL

**Решение:** хранение на SQLite, весь SQL заперт в `server/src/store.ts`.

Тот же принцип, который спецификация применяет к Redis («не раньше, чем
появится второй инстанс»), применён к базе. Один файл, ноль инфраструктуры,
бэкап — это `cp`.

Драйвер — встроенный `node:sqlite` из Node 24, поэтому **нативных сборок нет
вовсе**: `pnpm install` ничего не компилирует, и развёртывание не зависит от
компилятора на машине.

**Цена:** один процесс-писатель. Для этого масштаба неважно. Переход на
Postgres перепишет только `store.ts`.

---

## Порядок сборки

Шли строго по §15 спецификации: ядро без сети → симуляция → хот-сит → сеть →
персистентность → Чары и Архимаги → история и уведомления.

Спека настаивала не пропускать симуляцию, и это оправдалось: она вскрыла
[противоречие в целевых показателях §11](толкования-правил.md#целевые-показатели-11-противоречат-друг-другу),
которое иначе всплыло бы на живых плейтестах через месяц.

---

## Симметричный режим остался как настройка

**Решение:** режим без Архимагов и Чар не выброшен после Этапа 6, а оставлен
переключателем `Room.symmetric`.

На нём проверялась голая механика узлов и Порога, и он полезен для быстрой
партии и для отладки: когда что-то ломается, первым делом стоит проверить,
ломается ли оно без тридцати карт.

---

## Предзаявки отвергаются явно, а не игнорируются

**Решение (Этап 1, снято на Этапе 6):** пока эффекты не реализованы, заявка
с предзаявками отвергалась с отдельным кодом ошибки.

Молчаливое игнорирование — тот класс бага, который всплывает через месяц как
«сервер посчитал неправильно». То же правило действует сейчас для двенадцати
карт, ждущих расширения заявки: они перечислены в `NEEDS_PLAYER_INPUT`, и
тест падает, если карта не учтена ни в одном списке.

---

## Проверка сети — не на этой машине

**Решение:** ничего не запускается локально; интеграционный тест через
настоящие сокеты написан, но по умолчанию пропускается.

Игровая логика от этого не пострадала: комната принимает колбэк отправки,
поэтому все правила проверяются в процессе, без единого открытого порта.
Разделение оказалось удачным само по себе.

```bash
RAZLOM_SOCKET_TESTS=1 pnpm --filter @razlom/server test
```
