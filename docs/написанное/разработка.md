# Руководство разработчика

С чего начать, как работать и что проверять перед коммитом.

## Окружение

| Что | Версия | Зачем именно она |
|---|---|---|
| Node | 24+ | встроенный `node:sqlite` появился в 22.5 и стабилизировался к 24 |
| pnpm | 11 | ставится через `corepack enable` |
| git | любой | |

Нативных зависимостей нет. `pnpm install` ничего не компилирует.

```bash
corepack enable
pnpm install
pnpm typecheck && pnpm test
```

Если `pnpm install` пишет `Ignored build scripts: esbuild` — это ожидаемо и не
ошибка. Почему так и откуда это взялось — в [граблях](грабли.md#pnpm-11-и-сборочные-скрипты).

## Команды

Из корня:

| Команда | Что делает |
|---|---|
| `pnpm test` | все тесты всех пакетов |
| `pnpm typecheck` | `tsc --noEmit` по всем пакетам |
| `pnpm sim` | отчёт по балансу, см. [рецепт](рецепты.md#проверить-баланс) |
| `pnpm dev` | клиент в режиме хот-сит на `localhost:5173` |

По пакету:

```bash
pnpm --filter @razlom/core test
pnpm --filter @razlom/server start          # сервер, см. развёртывание
./node_modules/.bin/vitest run --root packages/core   # быстрее, без pnpm
```

## Порядок работы

1. **Сначала ядро.** Любое изменение правил начинается в `packages/core` и
   тесте к нему. Сервер и клиент только передают то, что решило ядро.
2. **Тест до кода**, когда меняются правила. Пограничные случаи §12 правил —
   образец: каждый стал отдельным тестом.
3. **Проверка перед коммитом:** `pnpm typecheck && pnpm test`. Оба должны быть
   чистыми; пропущенный тест допустим только один — сокетный, см. ниже.
4. **Толкование правил записывается.** Если правила молчат и вы что-то
   решили — это строка в [толкованиях](толкования-правил.md), а не только в коде.

## Соглашения

**Язык.** Комментарии, документация, сообщения коммитов и тексты ошибок — на
русском. Английский только в идентификаторах, ключах конфигов и цитатах из
вывода программ.

**Комментарии объясняют «почему».** «Что» видно из кода. Хороший образец —
`resolve.ts`: каждое неочевидное место объясняет, какой параграф правил оно
реализует и почему выбрано именно так.

**Ссылки на правила** — через параграф: `§5`, `§12`. Номера — из
`docs/исходное/razlom-pravila.docx` и `razlom-razrabotka.docx`.

**Ошибки правил** — только `RuleError` с кодом в кебаб-кейсе:
`throw new RuleError('not-enough-mana', '…')`. Тесты сверяют **код**, а не
текст сообщения: текст меняется, код нет. Хелпер — `expectRule` в
`packages/core/test/helpers.ts`.

**Строгий TypeScript.** Включены `noUncheckedIndexedAccess` и
`exactOptionalPropertyTypes`. Доступ по индексу возвращает `T | undefined` —
это сознательно.

**Ядро чистое.** В `packages/core/src` запрещены импорты извне пакета,
`Math.random` и обращения ко времени. Проверяется тестом
`architecture.test.ts`, а не договорённостью.

## Тесты

| Пакет | Тестов | Что покрывают |
|---|---:|---|
| core | 129 | правила, пограничные случаи §12, инварианты, эффекты, предзаявки, партия целиком |
| protocol | 7 | валидация входящих сообщений |
| server | 57 | проекции, комната, полный режим, история, постоянство, сокеты |
| sim | 9 | агент, детерминизм, свод метрик |
| client | 0 | **не покрыт** |

Три вида тестов, на которые стоит равняться:

- **Пограничные случаи** (`resonance.test.ts`) — по тесту на каждую строку
  таблицы §12 правил.
- **Инварианты** (`invariants.test.ts`) — 200 случайных раундов, проверка, что
  мана не появляется из ниоткуда, эссенция и Скверна растут только через
  события, входное состояние не мутируется.
- **Проекции** (`projection.test.ts`) — проверка со стороны получателя, что
  запрещённых полей нет **на любой глубине** объекта.

### Сокетный тест

`packages/server/test/sockets.test.ts` поднимает настоящий порт, поэтому по
умолчанию пропускается. Включается переменной:

```bash
RAZLOM_SOCKET_TESTS=1 pnpm --filter @razlom/server test
```

Запускать на сервере, а не на машине разработчика.

### Случайность в тестах

Партия создаётся с посевом, и Порог зависит от карты Разлома. Тест, который
ставит ману «впритык к Порогу», **обязан брать Порог из состояния**, а не
зашивать число. Иначе он плавает — такое уже было, см. [грабли](грабли.md#плавающие-тесты-из-за-порога).

## Git

Ветка `main`, удалённый репозиторий — `https://github.com/RinGinO/Razlom.git`.
Автор и отображение кириллицы в путях настроены **только для этого
репозитория**:

```bash
git config user.name          # RinGinO
git config core.quotepath     # false — иначе docs/написанное/ показывается кодами
```
