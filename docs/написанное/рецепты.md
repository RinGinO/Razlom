# Рецепты

Пошагово для типовых правок. Каждый рецепт проверен на реальном коде: пути,
имена функций и констант — настоящие.

---

## Добавить Чару

Пример: карта «Эхо», Эпоха II, цена 7, «+1 мана за каждый проигранный узел».

**1. Карта в колоду** — `packages/core/src/cards.ts`, массив `CHARMS`:

```ts
{ id: 'echo', name: 'Эхо', epoch: 2, price: 7 },
```

Колоды эпох собираются из `CHARMS` автоматически, отдельно регистрировать не
нужно.

**2. Эффект** — `packages/core/src/effects.ts`. Одна маленькая функция на один
вопрос:

```ts
/** Эхо: +1 мана за каждый проигранный узел. */
export function echoBonus(p: PlayerState, lost: number): number {
  return has(p, 'echo') ? lost : 0;
}
```

**3. Вызов в точке разрешения** — `packages/core/src/resolve.ts`. Найдите фазу,
где эффект срабатывает, и вызовите функцию там. Для этого примера — в блоке
«Возврат».

**4. Тест** — `packages/core/test/cards.test.ts` или `effects.test.ts`. Выдать
карту хелпером `grant`, разыграть раунд, проверить результат.

**5. Проверка честности разметки** пройдёт сама: она ищет `'echo'` в
исходниках ядра. Если тест падает с «Чара нигде не учтена» — вы забыли шаг 3.

### Если карте нужно решение игрока

Сначала определите тип решения — механизмы уже есть:

| Решение | Механизм | Где |
|---|---|---|
| цвет при покупке | `NEEDS_COLOR` + `pick.choice` | Столп, Друид |
| обмен эссенции | `EXCHANGE_PHASE` + `exchanges` | Родник, Алхимик, Тигель |
| цель среди соперников | `TARGETED` + `targeted` | Печати, Клеймо |
| реакция на исход | `ACTIVATABLE` + предзаявка `use-charm` | Громоотвод, Немой узел, Жатва |
| «раз в раунд / за эпоху» | `USE_LIMIT` | счётчик сбрасывается сам |

Добавьте id карты в нужную таблицу — валидация и счётчик подхватят её.

**Реактивные эффекты — только через предзаявку.** Если карта срабатывает «при
перегрузке» или «при проигрыше», разрешать её активацию после вскрытия нельзя:
игрок увидит исход и решит задним числом, и весь блеф рассыпается.

## Добавить Архимага

Как Чару, но в массив `ARCHMAGES` в `cards.ts`, с полем `minPlayers` — сколько
игроков нужно, чтобы карта раздавалась. Для персонажа, завязанного на узел,
которого нет при малом составе, ставьте порог по таблице масштабирования:
так Владыка Пустоты раздаётся только от шести.

`has(p, id)` одинаково проверяет и Чары, и Архимага — вызывать эффект можно
тем же способом.

## Изменить баланс

Все числовые ручки — константы в двух файлах:

| Ручка | Файл | Сейчас |
|---|---|---|
| коэффициент Порога по эпохам | `setup.ts` · `EPOCH_FACTOR` | 1,5 / 1,2 / 0,9 |
| награда за узел | `setup.ts` · `REWARD` | 2+1 / 3+1 / 5+2 |
| бонус Схождения | `setup.ts` · `CONVERGENCE_BONUS` | 2 / 3 / 5 |
| доход и предел запаса | `setup.ts` · `INCOME_PER_ROUND`, `DEFAULT_MANA_CAP` | 3 и 12 |
| цена Скверны | `setup.ts` · `ABYSS_MANA` | +2 маны |
| минимальный Порог | `setup.ts` · `MIN_THRESHOLD` | 3 |
| размер рынка и руки драфта | `setup.ts` · `MARKET_SIZE`, `DRAFT_HAND` | 6 и 3 |
| параметры карт | `effects.ts` · `SPRING_MANA`, `CONVERT_COST`, `BRAND_WEIGHT` | 3, 2, 2 |

Главная ручка по §11 спецификации — **коэффициент Порога**, вторая — награда
за узел, третья — доход и предел.

**Внимание:** тест `setup.test.ts` сверяет Порог со всеми 21 значением таблицы
§5 правил. Меняя `EPOCH_FACTOR`, вы меняете правила — обновите таблицу в тесте
и запишите решение в [толкования](толкования-правил.md).

## Проверить баланс

```bash
pnpm sim --players 6 --games 2000 --buy-rate 0
```

| Флаг | По умолчанию | Смысл |
|---|---|---|
| `--players` | 6 | 2–8 |
| `--rounds-per-epoch` | 6 | 4, 6 или 8 |
| `--games` | 2000 | 10 000 даёт устойчивые цифры за минуту |
| `--policy` | heuristic | `random` годится только для нагрузки |
| `--buy-rate` | 0,25 | доля раундов с покупкой; `0` — чистый замер |
| `--risk` | 0,4 | агрессия агента |
| `--seed` | 1 | посев |
| `--json` | — | отчёт машиночитаемым |

**Как читать.** Внизу отчёта — семь коридоров из §11 спецификации с пометкой
«ок» или «мимо». Абсолютные значения зависят от `--risk`: подкручивать
агрессию, пока цифры не сойдутся с целевыми, — значит подгонять ответ под
ответ. Смотрите на **форму**: давление должно расти от эпохи к эпохе при любом
риске.

**Когда сводка врёт** — смотрите сырые раунды:

```bash
cd packages/sim && ./node_modules/.bin/tsx src/debug.ts 6 10
```

Показывает по раундам Порог, суммы на узлах и ману каждого игрока. Именно так
нашлись все три ошибки агента — см. [грабли](грабли.md#агент-симуляции).

## Добавить сообщение протокола

Пример: клиент просит историю отдельно.

**1. Схема** — `packages/protocol/src/messages.ts`, в
`clientMessageSchema`:

```ts
z.object({ t: z.literal('get_history'), fromRound: z.number().int().min(0) }),
```

Ограничивайте всё: длины строк, диапазоны чисел, размеры массивов. Сообщение
приходит из браузера, а браузер не наш код.

**2. Ответ сервера** — там же, в типе `ServerMessage`.

**3. Маршрут** — `packages/server/src/server.ts`, в `switch (msg.t)`.
Мутирующие сообщения оборачиваются в `room.run(...)`: очередь гарантирует,
что два сообщения в одну миллисекунду обработаются по одному.

**4. Метод комнаты** — `packages/server/src/room.ts`.

**5. Тесты** — схема в `protocol/test/messages.test.ts` (в том числе что
мусор отвергается), поведение в `server/test/room.test.ts`.

Полный список сообщений — в [справочнике протокола](протокол.md).

## Добавить поле в проекцию

`packages/server/src/project.ts`. Правило одно: **проекция собирается с нуля**.
Добавляйте поле только в той ветке, где его можно показывать этому игроку, и
не заводите поле со значением `null` «для остальных» — у остальных ключа быть
не должно вовсе.

После — тест в `projection.test.ts` со стороны получателя: у кого поле есть,
у кого его нет. Проверять через `Object.keys(view)`, а не через
`view.field === undefined`: второе пропустит `{ field: undefined }`.

## Добавить интерактивную фазу

Понадобится, например, для отдельного объявления цвета Друидом или для
интерактивного Схождения.

1. Значение в тип `Phase` в `core/src/types.ts`.
2. Функции `resolveX` в ядре — без побочных эффектов.
3. Ветка в `Room.tryAdvance` и `Room.everyoneReady` в `server/src/room.ts`.
4. Отмена готовности: разрешить `unready` в новой фазе.
5. `notifyLastPlayer` — добавить фазу в список интерактивных, иначе не будет
   уведомления «ждём только тебя».
6. Сообщение протокола и его схема.
7. Экран клиента.

Прежде чем начинать — прочитайте [грабли про фазы](грабли.md#фазы-которых-нет):
три фазы из типа сервер не использует никогда.
